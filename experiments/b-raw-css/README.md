# 条件B — 無規律な素の CSS（対照群）

Tailwind を外しただけで、規約を導入しなかった場合を再現する対照群。
**推奨構成ではない。** 比較のために意図的にこの形にしてある。

## ファイル構成

```
render.mjs                 意味DOM を生成する（class 名は見た目を表す）
shell.html                 ページの外枠
style.css                  すべてのスタイル（1 ファイル）
scripts/                   条件C と同一（JS の差は測定対象ではない）
```

## どこを変えるか

| やりたいこと | 変える場所 |
|---|---|
| 色・余白・字面・角丸を変える | `style.css` の該当セレクタを個別に探して直す |
| 新しい見た目を丸ごと作る | `style.css` に規則を追加する（既存を打ち消す必要がある） |
| ある役割の見た目を変える | `style.css`（class 名が見た目ベースなので役割から引けない） |
| 状態（期限切れ等）の見た目 | `style.css` の `[data-card-state=...]` 節 |
| カードが狭い場所でどう畳まれるか | `@media (max-width: 640px)` — ただし viewport 基準 |
| 新しいカード型を足す | `contracts/cards.schema.json` → `render.mjs` の `bodies` → `style.css` に規則追加 |

## 規律

規約はない。class 名は `blue-box` / `gray-row` / `big-text` のように見た目を表す。
token も layer も無いため、同じ色が複数箇所に書かれている。

## この条件の既知のコスト

- 同じ色を変えるのに複数箇所を直す必要がある
- 後から足した規則が既存を打ち消すため、詳細度が上がり `!important` が出る
- dark mode は色を全部書き直している
