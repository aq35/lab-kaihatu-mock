## Step 3 — 商品選定（最大3をread-only調査→1件）

```
候補: ① HHKB Professional HYBRID Type-S（PD-KB800BS, ¥36,850）
      ② Elgato Stream Deck MK.2（~¥25,000 前後）
      ③ REALFORCE（東プレ・矢印あり）
実在確認: ①型番・公式ページ・価格 確認済（PFU ダイレクト）。②③は概略のみ。
販売確認: ①現行販売（公式店）。在庫数は UNKNOWN。
探究できる問い: ①「開発者向けなのに矢印キーが無い ¥36,850。効く制約か毎日の欠陥か」＝鋭い非対称。
      ②「既にあるショートカットを物理ボタンにする価値」＝やや弱い。③①の代替に回すのが有効。
Ownerとの接点: ① Owner は長時間タイプする開発者。道具の良し悪しが日々に直結。最も自分事。
選定・不選定理由: ① を選定。価格帯内・実在明確・価値の分岐が鋭い・誤解されやすい（“キーが少ない=劣る”）・
      スペック比較を超えた問い（矢印キー欠如は制約か欠陥か）を作れる。②は問いが弱い。③は代替として活用。
```

## Step 6 — ONE Hook（実装前に freeze）

```
ONE Hook: 「プログラマのために作られた ¥36,850 のキーボードが、コーディングに要る“矢印キー”を捨てている。
  これはあなたの手に効く制約か、それとも毎日つまずく欠陥か。」
Ownerとの接点: Owner は毎日コードを書く。矢印キーの有無は自分の指の話。
予想される直感: 「¥36,850 でキーが少ないのは割高／不便そう」。または「HHKB は良いらしい」という漠然。
直感を揺らす事実: 矢印キー“欠如”は仕様。Fn 併用で代替する設計。独立レビューは
  『矢印多用者には dealbreaker、ホームポジション中心なら快適』と条件で割れる（＝優劣でなく適合）。
購入判断との関係: あなたが「矢印キーを常用する」か「ホームポジション/Vim 中心」かで、
  同じ商品が“不要”にも“最適”にも振れる。ここが買う/買わないを分ける。
画面内で提示する答え: あなたの入力条件（矢印の使い方・用途・携帯性・学習許容）を選ぶと、
  価値が出る条件/出ない条件・欠点・代替・UNKNOWN を画面内で提示。外部検索に出さず答える。
反証条件: 「矢印キーを常に使う／すぐ使いたい／据え置きで携帯性不要」なら価値は出にくい、と明示する
  （良い点だけを見せない）。感触の好みは実機依存＝UNKNOWN と明示。
```

## 画像方針（rights + artifact CSP への正直な対応）
- artifact の CSP は外部画像を埋め込めず、権利条件も不明。よって**公式写真は埋め込まず source へリンク**する。
- 画面の主要ビジュアルは**自作の「配列の模式図」**（60% 配列・矢印キーが無いこと・Fn レイヤを示す）。
  これは実写ではない旨を明示し、AI 生成の実写や型番違いの流用はしない（§5 遵守）。
- この商品の hook は“無い矢印キー”そのものなので、模式図が写真より hook に直接効く（制約を強みに転換）。

## Exploration 5 段構成（Step 7）
1. Reality: 模式図＋正式名称・型番・メーカー・販売/価格・観測日時（＋公式写真 source）。
2. Hook: 上記 ONE Hook を提示（結論を隠しすぎない／clickbait にしない）。
3. Try Your Situation: 条件を選ぶ（①矢印キーの使い方 ②主用途 ③携帯性 ④学習許容）。
   各選択の**前に**「これを変えると“矢印キー問題があなたに致命的か些細か”が変わる」と payoff を明示。
4. Reveal Reality: 価値が出る条件/消える条件・変わること/変わらないこと・公式 vs 独立・欠点・代替・UNKNOWN。
   各主張から source（証拠確認用の外部リンクのみ。中心の答えは画面内）。
5. Decision: 購入ボタンは置かない。欲しい/条件付き/比較したい/不要/まだ判断できない を選び、理由を確認・修正。
