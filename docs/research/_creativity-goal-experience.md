# 小実験: AI の創造をフロントエンドで感じられるか（実装前に凍結）

```
凍結時刻: この doc の commit 時点（実装より前）
目的: 既存 UI の整形ではなく、1 つの研究用 Goal Experience を題材に、
      見たことのない「体験の捉え方」を 3 つ発想し、実際に触れる frontend にする。
      創造性の厳密な証明ではなく、Owner が画面から発想の違いを感じ取れるかを最小の実物で確認する。
題材: fixture.json（低リスクな研究用 Goal。下書き保存のみ・外部送信なし・本番非接続）
制限: 3 案まで / 1 fixture / 研究用のみ / framework・grammar・自動進化・DB・評価基盤を作らない /
      Foundry 非実装 / まず 3 案を Owner へ見せてから拡張。
```

## Step 1 — 材料（外観をコピーしない。変化・時間・因果・不確実性・発見の“感じさせ方”を抽出）

3 方向から原理を集めた:

1. **現実の行動・自然現象** → 航海（voyage）。
   抽出: 進捗を「出発港から目的地までの距離」で感じさせる。確かな海（測深済み）と未知の海（霧・
   未測深）の**境界**が一目でわかる。因果は航路の曲がりで表す。時間＝空間位置。
2. **Web 以外の道具・表現** → 実験ノート／証拠の出所（provenance ledger）。
   抽出: 主張を根拠に**線でつなぐ**。線の強さ＝確からしさ。根拠のない主張は宙に浮く。
   「何に支えられ、何が仮定か」「空欄（未検証）」を主役にする。
3. **一見 KAS と関係ない分野** → 往復書簡／会話／記憶（dialogue）。
   抽出: 出来事を**時間をまたぐ対話**として語る。話し手が「ここは確か」「ここは自信がない」を
   口調で区別する。不確実性を隠さず明言する関係性。

## Step 2 — 体験コンセプト 3 案（実装前の記録）

### 案 A: voyage（航海図）
```
着想源: 航海・海図
中心となる比喩または原理: 依頼＝出発港、Goal＝目的地。過ぎた海（理解→調査→判断→実行→確認）は
  描かれた航路、これから＝霧と未測深。現在地に「確かな海／未知の海」の境界線がある。
Ownerに最初に感じてほしいこと: 「今どこまで進み、確かなことと未知のことの境目はどこか」
情報をどのような関係として見せるか: 時間＝距離、因果＝航路の曲がり、不確実性＝霧の濃さ・未測深記号。
通常のdashboard/card UIと何が違うか: カードの積み重ねでなく、港→目的地への一本の航路。進捗＝空間位置。
失敗するとしたら何か: 比喩が飾りになり情報が読み取りにくい／横方向の道が mobile で破綻。
変える軸: 空間構造・時間の表現・不確実性・完了までの物語（4）
```

### 案 B: ledger（証拠の台帳／因果グラフ）
```
着想源: 科学実験ノート・証拠の出所(provenance)
中心となる比喩または原理: 「決めたこと」が「調べたこと」に線でつながる依存グラフ。
  線の強さ＝確からしさ(verified/observed/claimed)。仮定だけの判断は支えが宙に浮く。
Ownerに最初に感じてほしいこと: 「この判断は何に支えられ、どこが仮定なのか」
情報をどのような関係として見せるか: 判断↔証拠の依存関係。判断を選ぶと、支える証拠が光り、
  支えていない（＝仮定・未検証）が可視化される。stillUnknown は「切れた線」として現れる。
通常のdashboard/card UIと何が違うか: 情報が並ぶのでなく、つながりと欠落を見せる。空欄が主役。
失敗するとしたら何か: グラフが複雑で読めない／mobile で線が破綻。
変える軸: 情報の現れ方・Goalと証拠の関係・不確実性の感じさせ方（3）
```

### 案 C: dialogue（往復書簡）
```
着想源: 往復書簡・会話・記憶
中心となる比喩または原理: Goal 全体を Owner と KAS の時間をまたぐ対話に。KAS は一人称で
  「あなたはこう頼んだ→私はこう理解した→調べた→こう決めた→でもここは分からない→次はどうしますか」
  と語り、確かめたことと仮定を口調で区別する。
Ownerに最初に感じてほしいこと: 「KAS が相棒として、分かったことと分からないことを正直に話している」
情報をどのような関係として見せるか: 時間＝対話の往復。証拠＝発言の傍注。不確実性＝KAS の告白。
通常のdashboard/card UIと何が違うか: 一覧でなく読み進める語り。KASとOwnerの関係が主役。
失敗するとしたら何か: 単なるチャット UI の着せ替えに見える／長文で操作性が落ちる。
変える軸: KASとOwnerの関係・時間の表現・完了までの物語（3）
```

**3 案の弁別（禁止事項の確認）**: 色/余白/角丸/font だけの違いではない。3 案とも同じカード配置の variation ではない
（voyage＝一本の航路、ledger＝依存グラフ、dialogue＝時間の対話）。表面模倣（Apple/X 風）でもテンプレ名選択でもない。
3 案すべてが dashboard にはなっていない。

## 必須条件（Step 3）

reduced motion 対応・外部送信/本番データ/本番 credential を使わない。
