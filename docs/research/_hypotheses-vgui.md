# Verified Generative UI（VGUI）仮説 — 結果より先に凍結

このファイルの追加コミット SHA が凍結の証拠。
中心思想: **AI は完成した CSS を書かない。意味を固定したまま多数の視覚候補を生成し、
ブラウザ観測と Owner の選択で最適な表現を探索する。**

対象 surface: KAS の card（ACTION_APPROVAL / OWNER_QUESTION / OUTCOME_UNKNOWN_REVIEW / RESULT_REVIEW / INFORMATION）。
理由: 判定基準（危険操作の誤認・重要情報の見落とし・判断時間）は Owner UI でのみ意味を持つ。

## パイプライン
```
意味契約(固定) → 制約付き生成文法 → N 個の表現仮説 → Native HTML/CSS へ展開
  → 実ブラウザ観測 → 安全/可読性/性能で淘汰 → 生存案を Owner へ → 選択 → 次世代生成
```

## 閉じた Recipe との違い
- 固定 enum ではなく **連続パラメータ + 制約**（density:0.32 のような値）
- パラメータは CSS へ 1:1 対応させない。compiler が複数仮説へ展開し、ブラウザ結果を観測する
- 1 案実装ではなく **複数案を競争**させ、観測で淘汰する

## 凍結する仮説
- V1: 生成した 12 案のうち、**ブラウザ観測（安全/可読性/性能）で相当数が淘汰される**
  （淘汰は自己申告でなく実測。少なくとも 1 案は hard 制約違反で落ちる）
- V2: 生存案は **意味 DOM が全案 byte 一致**（表現だけ違い、意味契約は不変）
- V3: 生存案は **連続パラメータ空間で明確に異なる**（enum 選択より多様。param 距離 + computed style 差）
- V4: 淘汰器は既知の危険を捕まえる（required field を隠す案・contrast<4.5 の案・reduced-motion 無視の案を落とす）
- V5: 決定論的探索: 同じ seed から同じ 12 案・同じ生存集合（再現性。乱数で多様性を装わない）
- V6: 選択 → 次世代で、勝者パラメータへ寄せた第 2 世代が生成できる（進化ループが動く）
- V7: 生成した全 CSS を知識化しない。**複数 fixture/Goal で再現した規則だけ**が PROPOSED 候補になり、
  自動昇格しない（Owner 選択 + 再現が昇格条件。self-eval で ENABLED にしない）

## 反証条件
- V1 反証: 12 案すべてが観測を通過（淘汰が起きない = 観測に意味がない or 生成が保守的すぎる）
- V3 反証: 生存案が実質同一（連続空間が enum と同じ天井）
- V4 反証: 危険な案が淘汰をすり抜ける（観測器の欠陥）
- V5 反証: 同 seed で結果が変わる

## 判定対象（CSS 品質ではない）
Owner が正しく判断できたか / 判断時間 / 危険操作の誤認 / 重要情報の見落とし / 生成案の視覚的多様性 /
意味契約違反 / accessibility / performance / 選択から次世代が改善したか / 未知の表現を作れたか。
**Owner 実測が無いものは SELF_TESTED。自己評価を verification に昇格しない。**

## 禁止（固定フレームワークにしない）
生成した全 CSS を知識保存しない / 一度選ばれただけの表現を標準化しない / Owner の好みを普遍正解にしない /
自己評価で表現規則を昇格しない / 汎用 Web builder を作らない / KAS の意味契約と検証器だけを所有する /
CSS は使い捨て生成物 / 複数 Goal で効果が再現した規則だけ候補にする。

これは Foundry の先行実装ではない。「将来 Foundry が UI 表現をどう獲得するか」を小さく検証する研究。
