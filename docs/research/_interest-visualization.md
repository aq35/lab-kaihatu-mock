# 小実験2: 収集情報から「興味の入口」を視覚的に創る（実装前に凍結）

```
凍結時刻: この doc の commit 時点（実装より前）
題材: AI コーディング支援は本当に開発を速くするか（Owner が選択）
入力: experiments/interest-visualization/material.json（ライブ Web 検索で収集した実データ。
      各 item に source / observed_at / evidence_level / kind(fact/claim/inference) / relations / counter / unknowns）
Owner 既知の関心（アンカー・確認済み）: AI エージェントの実力・検証・不確実性の扱い
守ること: source と視覚を結ぶ / fact・claim・inference・unknown を区別 / 反対証拠を隠さない /
      誇張しない / 視覚的重要度を証拠強度と混同しない / provider failure を不在としない /
      AI が推測した関心を Owner の確定嗜好として保存しない / production・Foundry へ自動接続しない。
```

## Step 1 — 興味の種（根拠つき）

「AI が面白いと思ったこと」であり、「Owner が実際に興味を示したこと」ではない（後者は Step 5 で観測）。

### 種1: 同じ問いに真逆の RCT（+55% 速い vs −19% 遅い）
```
根拠: copilot_rct（55.8% 速い）× metr_rct（19% 遅い）。ともに RCT。
なぜ面白い可能性があるか: 「AI は速い/遅い」の二択が、実は両方 RCT で出ている。矛盾に見えて条件が違う。
まだ分からないこと: 何がこの符号を分けるのか（タスク型か母集団か）。reconcile_tasktype は未検証の仮説。
誇張になる条件: 「AI は開発を遅くする（と証明された）」と一般化すること。METR は熟練×既知 repo に限る。
```

### 種2: 体感と実測の乖離（+20% 速く感じるが −19% 遅い）
```
根拠: metr_rct（体験後も +20% 速いと信じた／実測 −19%）＋ dora_survey（75% が生産性向上を実感）。
なぜ面白い可能性があるか: 「速く感じる」ことそのものが測定対象になり、しかも客観と逆。Owner の関心
  （検証・不確実性）に直結する: 実感は証拠ではない、という主題。
まだ分からないこと: 乖離の原因（労力の再配分か、認知バイアスか）。reconcile_perception は推測。
誇張になる条件: 「開発者は AI に騙されている」と断じること。乖離の機序は未確定。
```

### 種3: 速度の裏で静かに増える負債（重複 8 倍・churn 増 → 安定性 −7.2%）
```
根拠: gitclear（重複ブロック 8 倍・churn 7.9%）→ dora_survey（安定性 −7.2%）。機序の連鎖。
なぜ面白い可能性があるか: 「速さ」の指標だけ見ると見えない負債が、別指標に現れる。原因の連鎖。
まだ分からないこと: AI が原因か（相関のみ）。重複増が実害（障害）に結びつくか。
誇張になる条件: 「AI がコードを壊す」と因果として断言すること。GitClear/DORA は相関。ベンダー立場もある。
```

### 種4: 証拠の強さと立場がバラバラ（RCT / 相関 / ベンダー・自社研究）
```
根拠: copilot_rct（GitHub 自身が関与）／metr_rct（非営利 RCT）／gitclear（製品ベンダー・相関）／dora（調査・相関）。
なぜ面白い可能性があるか: 同じ話題でも「誰が・どんな強さで」言っているかが全然違う。視覚的な目立ちと
  証拠の強さを混同しない、という規律そのものを体験にできる。
まだ分からないこと: 各研究の再現性。利害関係が結論をどれだけ歪めるか。
誇張になる条件: 立場のある研究を、無条件に同格の「事実」として並べること。
```

## Step 2 — 情報の形の判断

題材名や業界ではなく、item 同士の関係から選ぶ。この情報の骨格は:
- **対立**（copilot ↔ metr）→ 論点/対立マップ
- **主観↔客観の乖離**（体感 vs 実測）→ 二層・断面（felt / measured を重ねる）
- **原因の連鎖**（重複・churn → 安定性低下）→ 因果グラフの断片
- **証拠強度の差**（RCT / 相関 / 自社）→ 強度を独立チャネルで示す（大きさ＝重要度にしない）
- **未解決**（因果・一般化・乖離の理由）→ 未解決領域の可視化

固定テンプレートに当てはめず、上を組み合わせて 3 つの「焦点の違う入口」にする。

## Step 3 — 異なる3つの入口（実装前の記録）

### 案A: 既知の関心（検証と不確実性）
```
注目させたい発見: 「速く感じる」は測定対象であって証拠ではない。実感(+20%,75%)と実測(−19%,−7.2%)の乖離。
使用する根拠: metr_rct / dora_survey / reconcile_perception（inference と明示）。
最初に見せるもの: 体感メーターと実測メーターの二層。既定は「体感」表示で、切り替えると実測に反転する。
どのように探索させるか: felt ⇄ measured を切り替え、各主張の evidence_level と kind を開いて source へ。
Ownerが抱くと予測する問い: 「自分は AI で速くなったと“感じて”いるだけかもしれない。どう検証する？」
単なる要約と何が違うか: 数字を並べるのでなく、主観と客観の“ズレ”そのものを操作対象にする。
```

### 案B: 意外な接続（矛盾を溶かす地形）
```
注目させたい発見: +55% と −19% は矛盾でなく、タスクの型（greenfield↔familiar/複雑）と経験で分かれうる。
使用する根拠: copilot_rct / metr_rct を 2 軸の地形に配置。reconcile_tasktype（未検証の inference と明示）。
最初に見せるもの: 「速い/遅い」ではなく、2 軸のフィールド上に各研究が置かれた地図。
どのように探索させるか: 各研究をたどると母集団・タスク・符号が出る。空白領域（未検証の中間）を強調。
Ownerが抱くと予測する問い: 「自分の現場は地図のどこ？ そこでは速い側か遅い側か」
単なる要約と何が違うか: 対立を勝敗でなく“条件の地図”に変え、未検証の空白を発見させる。
```

### 案C: 反対・不足（証拠の強さと欠落）
```
注目させたい発見: 「AI は速い」を主張する証拠と反証を、強さと立場つきで並べると、強い反証と弱い根拠が見える。
使用する根拠: 全 item。各 evidence_level（RCT/相関/自社）と kind、counter、unknowns を前面に。
最初に見せるもの: 「AI は開発を速くする」という主張に対する 賛成/反対 を、証拠強度の軸で並べた対立マップ。
どのように探索させるか: 主張を選ぶと支持・反証・未解決が出る。視覚の大きさは均一、強度は別チャネル（記号）で示す。
Ownerが抱くと予測する問い: 「一番強い反証は？ 一番弱い（でも派手な）主張は？ どこが未解決？」
単なる要約と何が違うか: 目立ち＝正しさ、にしない。証拠強度と利害関係を可視化し、未解決を隠さない。
```

**A/B/C は画面スタイル名ではなく、異なる「興味の入口」**（検証／地形／反証）。同じ material から作り、情報は削らない。

## Step 5（Owner 観測）・最終報告

案ラベルは伏せて提示（案A=verify / 案B=terrain / 案C=claim）。

### Owner の生の反応（実データ）
1. 最初に気になった: **案B の図**が一番興味を引いた。
2. 操作: 案B のつまみ（スライダー）を先に触ったが、**意味がよく分からなかった**。
3. もっと知りたい: 「賛否両論あるな」程度の感想しか出ない。ただし問いは出た →
   「**どういう使い方をすれば価値があり、価値がない場合はどういう特徴か**」。
4. 意外な関係: **意外性はなかった**。散らばっていて**どこに注目すればいいか分からない**。
5. 記事の切り口: 意外性、または「**どういう使い方がいいか**」のノウハウ。
6. 誤解: 全体的に**俯瞰した見方しかできなかった**。
7. 根拠が弱い部分: **深掘りまではしていない**印象（＝判定に至らず）。
8. 単なる情報整理に見えた案: **はい**。

### 最終報告
```
Topic: AI コーディング支援は本当に開発を速くするか
Collected material: 実収集 4 件 + 推論 2 件（Copilot RCT +55.8% / METR RCT −19%・体感+20% /
  GitClear 重複8倍・churn増 / DORA 安定性−7.2%）。すべて source 付き・AI 補完なし。
Interest seeds: ①真逆の RCT ②体感と実測の乖離 ③速さの裏の負債 ④証拠強度と立場の差。
Three visual entrances: A 検証(体感/実測の層) / B 地形(タスク型×経験) / C 対立マップ(証拠強度)。

Owner first attention: 案B の 2 軸の図（視覚的な引きだけは効いた）。
Owner interactions: 案B のスライダーを最初に操作（が、意味が伝わらなかった）。
Questions generated: 「AI コーディング支援は、どういう使い方だと価値があり／なく、その特徴は何か」。
Unexpected connection: なし。「タスク次第」は Owner にとって意外でなかった（＝直感どおり）。
Counterevidence noticed: 明確な言及なし（俯瞰止まりで反証に踏み込んでいない）。
Chosen article angle: 「使い方の条件（価値が出る場面／出ない場面とその特徴）」。次点「意外性を軸に」。
Rejected angles: 単なる賛否両論の俯瞰 → 意外性が出ず「情報整理」に見えるため不採用。
Misleading presentation: 誇張の指摘は無し（むしろ弱い）。別問題として、案B のスライダーは
  「操作できるが payoff が読めない」＝機能はあるが価値が伝わらない装飾になっていた。
What created curiosity: 案B の空間的な図の"見た目の引き"のみ（最初に目を引いた）。
What was only decoration: 案B のスライダー操作（意味不明）、案C（情報整理に見えた=Q8 yes）。
  全体として"俯瞰"に留まり、好奇心の点火には至らなかった。
Foundry hint (PROPOSED / KAS 本体へ実装しない):
  - IH-1: 好奇心は「バランスの取れた俯瞰」では立たない。両論を公平に並べるほど"情報整理"に落ちる。
    立てるには ONE の鋭い hook（意外な非対称／自分に刺さる一問）に絞る必要がある。
  - IH-2: 小実験1 の「関係の組み替え＞散文」を精緻化: 関係マップでも、示す関係が"期待どおり(賛否)"
    だと好奇心は出ない。効くのは"期待を裏切る関係"＝非対称・自分事化。
  - IH-3: 操作は payoff が即座に読めないと装飾化する（案B スライダー）。インタラクションは
    「動かす→意味がすぐ分かる」まで設計しないと、むしろ混乱を生む。
  - IH-4: Owner が自ら出した価値軸は「使い方の条件（when valuable / when not）」。
    収集情報を"論争の地図"でなく"意思決定の指針"へ変換する入口の方が、この Owner には効く可能性。
Next small experiment（1 つだけ・実施は指示待ち）:
  3 入口をやめ、ONE 入口に絞る。known 関心＋反証＋非対称を 1 つの問いに束ねる。例:
  「あなたは AI で速くなったと"感じて"いる。だが、あなたの現場に一番近い実測(熟練×既知 repo)は −19%。
   では、どんな使い方なら＋に転じるのか？」— これで「もっと知りたい」が出るか 1 回だけ測る。
```

### 完了条件の判定 — すべて満たした（ただし主目的=好奇心は弱かった）
1. 実際の収集情報 1 件を使用した ✓（ライブ検索・source 付き）
2. 興味の種を根拠付きで抽出した ✓（4 件）
3. 同じ情報から異なる 3 つの入口を実装した ✓
4. 各情報から source を確認できた ✓（全カードに source ↗）
5. Owner が実際に触った ✓（案B スライダー）
6. 少なくとも 1 つ「もっと知りたい問い」が生まれた ✓（使い方の条件）
7. 少なくとも 1 つ、面白くなかった案も記録した ✓（案C=情報整理に見えた／全体も俯瞰止まり）
8. 記事に採用した切り口と不採用理由を記録した ✓（採用=使い方の条件／不採用=賛否の俯瞰）
9. production・Foundry へ自動接続しなかった ✓

### 好奇心が消えた場所（正直に）
- **題材**: 「賛否両論」は俯瞰になりやすく、hook が弱い題材だった（部分的要因）。
- **実装で均質化**: 3 案とも"debate を俯瞰する"点で読後感が近く、情報整理に収束した。
- **入口の踏み込み不足（主因）**: 論争の"地図"で止まり、鋭い hook / 使い方の示唆へ進まなかった。
  → 好奇心は「両論の俯瞰」ではなく「非対称・自分事・使い方の指針」で立つ、という限定つきの知見。

## 2 つの小実験の対比（Foundry へのメモ）
- 小実験1（Goal Experience）: 創造は「情報の関係の組み替え」で立つ（関係 > 散文）。
- 小実験2（Interest Visualization）: 関係の組み替えでも、示す関係が"期待どおり(賛否)"だと情報整理に落ちる。
  好奇心には「期待を裏切る非対称」＋「自分事化」＋「操作の即時 payoff」が要る。
  ＝ Owner が言う「知っている関心 ＋ 意外な接続 ＋ 考えを揺らす反証」を**別々の入口に分けず 1 つに束ねる**のが次の鍵。
