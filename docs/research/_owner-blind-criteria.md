# VGUI — 実 Owner blind comparison の判定基準（実施前に凍結）

```
凍結時刻: この doc の commit 時点（結果を見る前）
対象命題: VGUI の中心命題 —「同じ意味を持つ UI のうち、どの表現が
          安全で速い判断を生むか」を、SIMULATED_SELECTION ではなく
          現実の Owner の選択で判定する。
測る対象: 美観ではない。安全で速い判断。美観は副次評価としてのみ記録する。
```

## なぜ今これをやるか

これまでの VGUI は「生成 → 観測淘汰 → 進化」の**機構**が動くことを示した。
だが選択は `SIMULATED_SELECTION`（intent 中心に最も近い生存案を機械が選ぶ）だった。
中心命題「Owner にとって本当に有用か」は**未検証**のまま。

`SIMULATED_SELECTION` を現実の選択に置き換えないかぎり、統合レポートを書いても
「機構は動いたが有用性は未検証」以上には進めない。よって次の 1 サイクルは
範囲を広げず、実 Owner の実測だけを行う。

## 誰が測るか（重要な制約）

**AI は Owner になれない。** この測定の被験者は現実の人間（Owner 本人）である。
私（AI）が案を選んで数字を埋めることは、この実験の否定に等しい。したがって:

- 実測が済むまで、下表の結果セルは **UNMEASURED** のままにする。
- 私は結果を**シミュレートしない**。gen2 の再生成は、実 Owner の gen1 選択が
  返ってきて初めて走らせる。

まず 1 人・1 intent で計測系そのものを検証し、その後に複数 intent へ広げる。

## 対象 intent（今回の 1 本）

`quiet anticipation` / attention_path = identity → evidence → action → risk → context
（`docs/results/raw/vgui-pipeline.json` の grammar と同一。gen1 seed 7 / n 12 の生存 4 案）

## 提示と目隠し

- 生存 4 案を **案 A / 案 B / 案 C / 案 D** として提示（パラメータ・生成理由・
  世代は伏せる）。
- 案の**並び順はセッションごとにランダム化**する（順序効果の除去）。
- 4 案はすべて**同一の意味 DOM**（同じ 5 カード・同じ data-* 契約）。違うのは表現だけ。
  これは実施前に機械照合で確認する（V2 と同じバイト照合）。

## タスク（各案で同じ手順）

各案 1 枚ずつ、次を順に行い時間を測る。

1. **危険操作の識別（時間つき）**
   > 「この画面のカードの中から、"実行すると取り消せず、外部に影響する操作の
   >  承認を求めているカード" を 1 つ選んでクリックしてください。」
   - 計測: 案がアクティブになってから最初のカードクリックまでの時間。
   - 正解カード = `card_a1`（ACTION_APPROVAL / 外部送信・取り消し不可）。
   - **危険操作の取り違え** = 最初のクリックが `card_a1` 以外だった。
2. **重要情報の見落とし**
   > 「その承認カードの中で、"この操作のリスク" が書かれている箇所をクリック
   >  してください。」
   - 見つけた = `data-field="risk"` 領域内をクリック。
   - **見落とし** = リスク領域に到達できなかった / 別フィールドを誤クリック。

各案終了後、主観を 1 行記録（任意）。

## 全案を終えたあとの選択（gen2 へ渡す）

> 「最も速く・安全に判断できたのはどの案ですか。理由を一言で。」

その案のパラメータを `nextGeneration` へ渡し gen2 を生成する。
**「どれが好きか（美観）」ではなく「どれが安全で速い判断を生んだか」**を選ぶ。
美観は別欄に副次評価として残す。

## gen2 でも同じ測定を行い、gen1 と比べる

## 判定基準（実施前に凍結）

| 指標 | 成功条件 | gen1 実測 | gen2 実測 |
|---|---|---|---|
| 危険操作の誤認 | 0 件 | UNMEASURED | UNMEASURED |
| 重要情報の見落とし | 0 件 | UNMEASURED | UNMEASURED |
| 判断時間（危険カード識別） | gen2 が gen1 以下 | UNMEASURED | UNMEASURED |
| 主観評価（安全に判断できた感） | gen2 が同等以上 | UNMEASURED | UNMEASURED |
| 進化の再現性 | 別 fixture でも悪化しない | 未実施（複数 intent 段で） | — |

補足:
- 「危険操作の誤認 0 件」「見落とし 0 件」は**全案共通の絶対条件**。
  1 案でも危険カードを取り違えさせる表現があれば、その表現は観測淘汰を
  すり抜けた欠陥として記録する（＝淘汰基準に追加すべき候補）。
- 判断時間は n=1 では分布が取れない。今回は**計測系の検証**が主目的であり、
  gen1↔gen2 の**方向**（悪化していないか）だけを見る。確定は複数試行で。

## 計測系そのものの妥当性チェック（1 人でも確認できること）

- クリック→カード種別/フィールドの取得が正しいか（`data-*` 経由）。
- 時間計測が案アクティブ化を基準にしているか（読み込み時間を含めない）。
- 目隠し（案ラベルと実 cand-id の対応表は Owner に見せない）。
- 並び順ランダム化が効いているか。

## 反証の姿勢

- もし gen1 の 4 案すべてで誤認 0・見落とし 0・時間差なしなら、
  「この intent では表現差が判断安全性に効かない」という**帰無仮説の支持**であり、
  それも正当な結果として記録する（VGUI が無意味という意味ではなく、
  「この intent・この 5 カードでは差が出ない」という限定つきの知見）。
- 計測系が壊れていた場合は「再現しない」ではなく「まだ正しく測れていない」
  として counter-proof と同じ規律で扱う。
